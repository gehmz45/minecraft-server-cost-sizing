## 雨云游戏云的机器怎么挑：区域、NAT 和线路

**江苏镇江**是 NAT 网络，多个用户共用一个公网 IP，每台机器提供 15 个端口，也可以加钱换成独立公网 IP。开 MC 服完全够用，因为要用到的端口就三个：MCSManager 面板的 23333 和 24444，Minecraft 服务端的 25565。15 个额度绰绰有余。

## 先定服务端，再买机器

服务端类型决定了你需要什么版本的 Java，也决定了机器内存要买多大。五种主流选择：

- **原版（官方 server.jar）**：Mojang 官方发布，功能最干净，不加任何模组和插件。注意原版 jar **加不了模组**，想加模组必须换 Forge 或 Fabric。
- **Paper**：Spigot 的高性能分支，兼容大部分 Bukkit 和 Spigot 插件，优化选项多，适合想要更好 TPS 的生存服和小游戏服。
- **Fabric**：轻量级模组加载器，跟进新版本速度快，适合想玩最新版本模组的玩家。
- **Forge**：老牌模组加载器和 API，模组生态最全，整合包大多基于它。
- **Mohist**：融合 Forge 和 Bukkit/Spigot，能同时跑模组和插件。但 **Mohist 只更新到 1.20.2**，想在更高版本上同时跑模组和插件，这条路走不通。

Java 版本对不上，服务端连启动都启动不了：

| JDK 版本 | 对应 Minecraft 版本 |
| --- | --- |
| JDK 8 | 1.7 及以下 |
| JDK 11 | 1.8 ~ 1.16 |
| JDK 17 | 1.17 ~ 1.19 |
| JDK 21 | 1.20 及以上 |

表里没覆盖到的更新版本，以服务端下载页写明的 Java 要求为准，别照抄旧教程里的 openjdk-17。见过不少教程页面更新了日期，正文还停在 1.19 的示例上。

## 机器要买多大：单核、内存、带宽

**单核性能是硬门槛。** Java 版服务端从 1.18 之后对 CPU 单核性能要求相当高，建议选 CPU-Z 单核跑分 600 以上的机型，14900K、13900K、7950X、9950X 这类高主频 CPU 都是经过验证的选择。核数多但主频低的机器，跑 MC 反而不如少核高主频。

**内存 4 核 8G 是推荐起步配置。** 低于这个不是启动不了，2 核 4G 也能跑起一个原版小服，但玩家一多、再加上插件和模组，体验就会掉。有第三方教程估算 4 核 8G 可以支撑 10 到 15 名玩家同时在线，这个数字是教程作者的估算，不是官方承诺，实际能带多少人还取决于视距设置、插件数量和地形生成负载。雨云的游戏云支持后期升级内存，先买小一点、人多了再升，比一步到位买贵机型更划算。

带宽看上行，10Mbps 是底线。开服消耗的是上行带宽，下行再大也没用。10 人以内的原版服 10M 上行基本够，20 人以上建议往 15M 走，否则玩家容易卡在“正在加载地形”。

## 动态计费和固定计费，长期开服差在成本上

这一条前排教程基本没提，但它直接决定你一年花多少钱。

雨云游戏云有两种计费模式。**动态计费**在 CPU 占用率超过 20% 时会产生额外费用，每天有一定免费额度；**固定计费**按套餐价走，不随负载浮动。

偶尔周末开几小时、平时关机，动态计费确实便宜。但 MC 服务端是常驻进程，1.20 之后的高版本即使没人跑图，后台也在持续吃 CPU，20% 这条线很容易被顶穿。打算 7×24 小时挂着让朋友随时进来的，选固定计费，账单可预期。这个是计费规则本身推出来的结论，不是猜测。

另外年付通常有折扣，具体折扣力度和是否与其他优惠叠加，以购买页结算时显示的金额为准。

## 搭建流程：从装系统到朋友进服

1. **买机器**，区域按上一节的原则选，系统选 Debian 12，软件安装不勾选。
2. **NAT 机型先做端口映射**。在控制台的“NAT 端口映射”里新建规则，协议选 TCP+UDP，依次把 23333、24444、25565 三个内网端口各建一条。外网端口用系统随机分配的就行，提示被占用就自己填一个 10000 到 60000 之间的。**每个人的外网端口都不一样，不要照抄教程截图里的数字。**
3. **SSH 登录服务器**，用 PuTTY 或 MobaXterm 都行。先换 apt 源，用 `chsrc` 自动测速选最快的国内镜像。
4. **装 MCSManager 面板**。它有现成的安装脚本，Docker 版一条命令跑完，中途提示是否安装 Docker、是否配置镜像加速源，都选 Y 或直接回车用默认值。装完会显示面板地址和 Daemon 密钥，记下来。
5. **浏览器打开面板**，地址是公网 IP 加 23333 映射出来的那个外网端口。
6. **装对应版本的 JDK**。面板提供 JDK 安装脚本，选你要的版本就行。
7. **下载服务端 jar**，重命名成 `server.jar`。在面板创建实例，实例类型选“MC Java 版服务端”，Docker 镜像选对应的 JDK 版本，启动命令填：


java -Xms1G -XX:MaxRAMPercentage=90.0 -XX:+UseZGC -jar server.jar nogui


`-XX:MaxRAMPercentage=90.0` 限制 JVM 最多用系统内存的 90%，留 10% 给系统和面板；`-XX:+UseZGC` 启用 ZGC 垃圾回收器，需要 JDK 15 以上，低版本要去掉这个参数；`nogui` 表示后台无界面运行。

8. **改 eula.txt**。第一次启动必然报 `You need to agree to the EULA`，进“服务端配置文件”把 `eula.txt` 里的 `eula=false` 改成 `true`，保存。
9. **Docker 方式还要单独开端口**。在“容器化 → 开放端口”里新增一条配置，主机端口和容器端口都填 `25565`，协议选 TCP。少了这一步，服务端在容器里跑得好好的，外网就是连不上。
10. **再点开启**，等控制台出现 `Done`，服务器就起来了。客户端“多人游戏 → 添加服务器”，地址填 `公网IP:映射出的25565端口`，IP 和端口之间用英文冒号。

# -Xmx4G` 为实际内存值，再把启动命令换成 `bash run.sh`。

## 六个最容易卡住的坑

**三个端口都要映射。** NAT 机型只映射 25565，面板打不开；只映射面板端口，朋友进不去。23333、24444、25565 一个都不能少。

**Docker 容器里还要再开一次 25565。** 这是两个独立步骤，宿主机映射和容器端口开放缺一不可。

**关正版验证是有代价的。** `server.properties` 里的 `online-mode` 改成 `false` 后，没有正版账号的人也能进，但被 ban 了随便换个 ID 就能回来，公开服很容易被人搞破坏。小圈子熟人服可以关，公开招募的服建议开着，或者装白名单插件。

**换存档别忘了目录权限。** 删掉原来的 `world` 文件夹，把新存档改名成 `world` 放进去。如果服务端是用非 root 用户跑的，换完必须把目录属主改回去，例如 `sudo chown -R mcfabricuser:mcfabricuser /minecraft`，否则服务端读不到世界文件，起不来。

**模组要双端一致。** 服务端模组（比如连锁采集）本地和服务器必须版本完全一致才生效，客户端模组（小地图之类）不上传服务器也能用。Fabric 服还必须先往 `mods` 文件夹里放 Fabric-API，不然其他模组一个都不加载。

**性能不够先调视距，别急着加钱。** Paper 的优化入口是 `server.properties`、`spigot.yml`、`paper-global.yml`、`bukkit.yml` 四个文件，优先动视距和实体激活范围。改完用 `timings` 生成报告定位瓶颈，一次改一项，别一口气全调。
